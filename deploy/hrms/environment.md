# Environment and identity contract

The renderer contains deployment identifiers and paths only. Supply restricted `0600` environment files on the VPS; they are never generated from a fleet-wide `.env`, uploaded with release artifacts, or included in images. Bind mounts reject missing paths. The example UUIDs/domains are placeholders, not application rules.

## Company files

For each manifest slug, independently provision:

| File under `/opt/apps/hrms/env` | Required settings |
| --- | --- |
| `companies/<slug>/auth.env` | `DATABASE_URL` for restricted ops/entitlement reads; `KABIPAY_BOUND_DATABASE_URL` for exactly this company; `KABIPAY_BOUND_SCHEMA`; `KABIPAY_CLIENT_JWT_KEY_ID`; `KABIPAY_CLIENT_JWT_PRIVATE_KEY_FILE=/run/auth-secrets/client.key`; `KABIPAY_CLIENT_JWT_PUBLIC_KEYS` (only this company's RSA public key, exactly one tenant per key); `KABIPAY_SERVICE_TRUST_KEYS` (public organization service keys limited to this company); established Auth operator/client issuer/secrets and password settings as required by the existing Auth configuration |
| `companies/<slug>/runtime.env` | Restricted ops/entitlement `DATABASE_URL`; this company's bound URL/schema; `KABIPAY_CLIENT_JWT_PUBLIC_KEYS`; `KABIPAY_ORGANIZATION_DELEGATION_PUBLIC_KEYS`; `KABIPAY_SERVICE_TRUST_KEYS`; `KABIPAY_SERVICE_KEY_ID`; existing company business/Finance/notification delivery configuration |

The renderer fixes `KABIPAY_BOUND_TENANT_ID`, `KABIPAY_CLIENT_JWT_MODE=rs256`, `KABIPAY_AUTH_PLANE=client`, the policy **origin** and fixed endpoint maps. Every service has its own `KABIPAY_SERVICE_ID`, private service-key directory and `KABIPAY_SERVICE_PRIVATE_KEY_FILE=/run/service-secrets/service.key`. Use the configured key ID in each public trust entry. A common key ID may be used across different service identities only if their verification configuration is unambiguous; use distinct keys per service and company. Runtime env files must not contain Auth signing keys, other companies' credentials, migration/admin credentials, `KABIPAY_ORGANIZATION_PRIVATE_HTTP`, or plaintext test flags.

Public key JSON formats (paths inside containers):

```json
[{"kid":"company-client-v1","tenant_ids":["11111111-1111-4111-8111-111111111111"],"public_key_file":"/run/public-keys/company-client.pem"}]
```

```json
[{"kid":"organization-service-v1","service":"kabipay-organization","tenant_ids":["11111111-1111-4111-8111-111111111111"],"public_key_file":"/run/public-keys/organization-service.pem"}]
```

`KABIPAY_ORGANIZATION_DELEGATION_PUBLIC_KEYS` maps delegation key ID to public PEM file. Company Auth signing key mounts only into its Auth process. Service private keys mount only into the matching source service. Public verification files are in `config/public-keys`. PostgreSQL URLs must use verified TLS and the source registry's exact host/database/schema; bound runtime startup checks that registration and refuses a mismatch.

Private source proxy certificate `secrets/<slug>/tls/server.pem` + `server.key` must cover DNS `source-<slug>`. Its identity endpoint uses port8443; Employee/Leave/Attendance/Payroll/Performance/Workflow command endpoints use ports8444..8449 in that order. Port8450 serves only `/internal/private-events/delivery` and `/internal/private-events/ownership` with a 16KiB body limit and verified client certificates against `secrets/<slug>/tls/private-delivery-client-ca.pem`. Ports8451 (Payroll) and8452 (Employee) expose only `/internal/finance` over HTTPS with a 128KiB body limit; the Finance service secret remains required. No host ports are published. `config/tls/organization-ca.pem` is an explicit bundle for private source/policy/history HTTPS trust; hostname validation and certificate verification remain enabled. Rust clients also disable proxies and redirects. The policy certificate covers `organization-internal`. The policy proxy joins source and organization networks; the organization process itself joins organization + metadata networks only.

Private file paths must be normalized, distinct, non-overlapping company directories under HRMS `data/` or existing platform `data/private-files/`. Release resolves existing paths and refuses symlink aliases; it never creates/moves a company's data directory. Each company has a separate egress bridge for SMTP/HTTPS/Finance/webhook delivery. Its client Auth/business/maintenance services join that bridge; the central organization process does not. No inbound service ports are published by adding outbound connectivity.

Configure Finance origins explicitly in each runtime file: `KABIPAY_FINANCE_EMPLOYEE_URL=https://source-<slug>:8452`, `KABIPAY_FINANCE_PAYROLL_URL=https://source-<slug>:8451`, plus that company's independent `KABIPAY_FINANCE_SERVICE_SECRET`. The renderer supplies `KABIPAY_ORGANIZATION_HTTP_CA_FILE=/run/tls/organization-ca.pem` to the Finance client; its CA bundle must trust the source proxy certificate. Preflight requires HTTPS and validates every source file before any application startup, including when post-validation is skipped. Normal post-validation compares effective values in both actual Employee/Payroll container IDs without printing secrets. Existing secrets are never rotated automatically.

Company CDC schema must match `KABIPAY_BOUND_SCHEMA` (never hardcode `public`). Kafka provisioning derives its exact marker topic, connector table filters, unique `organization_cdc_<company UUID without hyphens>` role and `organization_company_<company UUID without hyphens>` replication slot. Source provisioning fails on inherited/broad privileges, other-database CONNECT or publications outside the canonical boundary; it never silently revokes other roles/PUBLIC. The DBA must review database/HBA grants while preserving current application access before provisioning. See the database project's security prerequisites. Company services/Auth must not receive the global operator HMAC key; use only the client RSA signer in Auth and appropriately scoped public verification configuration elsewhere.

No public unbound client/HMAC fleet remains. |

| `workers/inbox.env` | `ORGANIZATION_METADATA_DATABASE_URL` projection role; worker Kafka identity and PostgreSQL CA; Kafka group, brokers/quarantine topic; no ClickHouse credential or company DB URL. |

| `workers/capture.env` | Capture-only metadata role, Kafka capture identity, `CAPTURE_BINDINGS_FILE=/etc/organization/capture-bindings.json`, read-only proxy CA/client key/cert via `CONNECT_CA_FILE`, `CONNECT_CLIENT_CERT_FILE`, `CONNECT_CLIENT_KEY_FILE`. | `workers/control.env` | `CONTROL_BINDING_FILE=/etc/organization/control-binding.json`, `CONTROL_GROUP_ID`, `CONTROL_QUARANTINE_TOPIC=organization.control.quarantine`, Kafka control identity, restricted ClickHouse control writer. No PostgreSQL connection. |
| `workers/archive.env` | Archive-only metadata role, public service-verification keys, ClickHouse archive reader, TLS/mTLS server files, encrypted archive key/version/root/bindings. Archive encryption key is not mounted into consumers/organization/source services. |

Company workers use `KAFKA_BROKERS=kafka:9092`, exact `KAFKA_GROUP_ID` compatible with provisioned ACLs, `KAFKA_QUARANTINE_TOPIC`, `KAFKA_CA_FILE=/run/secrets/ca.crt`, `KAFKA_CERT_FILE`, `KAFKA_KEY_FILE`, and `POSTGRES_CA_FILE=/run/secrets/postgres-ca.crt`. Provision distinct Kafka certificate principals for inbox, history, reporting, capture, control and each Connect producer. The Kafka binding requires `inboxPrincipal`, `historyPrincipal` and `reportingPrincipal`; each reader can join only its own literal role group. The former shared `consumerPrincipal` is rejected. Never reuse one reader certificate between role secret directories. History/reporting/control add `CLICKHOUSE_URL=https://clickhouse:8443/`, their managed `CLICKHOUSE_USER`/`CLICKHOUSE_PASSWORD`, and the ClickHouse CA file used by `NODE_EXTRA_CA_CERTS`. Separate secret directories are under `secrets/workers/<role>`; mount targets are `/run/secrets`, except archive `/run/archive-secrets`. All public trust key files referenced by archive must be inside its own public verification mount/secret directory, never private source keys.

Organization reporting: `KABIPAY_ORGANIZATION_CLICKHOUSE_URL=https://clickhouse:8443/`, `KABIPAY_ORGANIZATION_CLICKHOUSE_USER=organization_projection_reader`, password file and CA file under `/run/organization-secrets`. Archive: `KABIPAY_ORGANIZATION_ARCHIVE_URL=https://archive:8444`, CA + client cert/key files under `/run/organization-secrets`. Organization service/delegation keys are also there with explicit absolute file variables. Its private TLS sidecar has a separate `secrets/organization/tls` directory.

Archive env must explicitly set `ORGANIZATION_ARCHIVE_ROOT=/var/lib/organization-archive`, `ORGANIZATION_ARCHIVE_KEY_FILE`, `ORGANIZATION_ARCHIVE_KEY_VERSION`, optional versioned `ORGANIZATION_ARCHIVE_READ_KEYS`, `ARCHIVE_BINDINGS_FILE`, `KABIPAY_SERVICE_TRUST_KEYS`, `ARCHIVE_TLS_KEY_FILE`, `ARCHIVE_TLS_CERT_FILE`, `ARCHIVE_CLIENT_CA_FILE`, `POSTGRES_CA_FILE`, and ClickHouse client settings, all using `/run/archive-secrets` for its own secrets. Apply documented UID/filesystem permissions to the archive data directory for the non-root Node image. No automatic data-directory creation is performed.

## Private audit, delivery and history

These files are provisioned independently of the public organization projection/archive workers. All mounts below are read-only; every bind uses `create_host_path:false`. Do not set `ALLOW_ISOLATED_PLAINTEXT` in a release. File contents must match the actual company UUID, source database/schema and current producer generation; a company selector received from a request never creates a binding.

| Process | Env file under `env/` | Host mounts under HRMS root | Required runtime contract / credential scope |
| --- | --- | --- | --- |
| Employee/Leave/Attendance/Expense/Notification/Survey/Analytics and `maintenance-<slug>` | `companies/<slug>/runtime.env` | Each process's `secrets/<slug>/private-events/<service>` to `/run/private-events`; maintenance uses its `maintenance` directory | Renderer sets `KABIPAY_PRIVATE_EVENT_KEYS_FILE=/run/private-events/keys.json`. Include only this company's audit/delivery encryption keys required by that process; no other company or operator scope. Maintenance runs `kabipay-tenant-maintenance`, preserving bound scheduled business work without the retired delivery poller. |
| Survey + Analytics audit readers | Same company runtime | Their own private-events directory plus shared CA mount | Renderer sets `KABIPAY_PRIVATE_HISTORY_CLIENT_FILE=/run/private-events/audit-client.json`, `KABIPAY_PRIVATE_HISTORY_CLIENT_CERT_FILE=/run/private-events/client.crt`, `KABIPAY_PRIVATE_HISTORY_CLIENT_KEY_FILE=/run/private-events/client.key`. Only metadata operator scope/purpose keys, its exact Kafka group/identity and operator-audit ClickHouse writer; no company encryption keys or source DB credentials. |

Private workers require `KAFKA_BROKERS`, `KAFKA_CA_FILE`, `KAFKA_CERT_FILE`, `KAFKA_KEY_FILE` and `PRIVATE_EVENT_GROUP_ID` (not the public worker's `KAFKA_GROUP_ID`). The Kafka admin binding requires distinct `auditPrincipal`, `deliveryPrincipal`, `operatorAuditPrincipal`; set audit/delivery `PRIVATE_EVENT_GROUP_ID` to `<consumerGroupBase>.audit.v1` / `<consumerGroupBase>.delivery.v1`, and operator audit to `organization-operator-audit.v1`, matching the provisioned ACLs. Use distinct provisioned Kafka principals and literal groups. Company audit consumes only `organization.audit.<UUID>`; operator audit consumes only `organization.operator_audit.metadata`. Delivery consumes `organization.delivery.<UUID>`, `.history.<UUID>`, `.work.<UUID>`, `.retry.1.<UUID>` through `.retry.3.<UUID>` and produces work/retry/history/`.dlq.<UUID>` under the same `organization.delivery` prefix. Every required private topic must have exactly partition0. Provision only corresponding read/write/describe/group ACLs; no fleet-wide wildcard or shared audit/delivery credentials.

All private workers/query processes require `CLICKHOUSE_URL=https://clickhouse:8443/`, `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`; renderer sets `NODE_EXTRA_CA_CERTS=/run/secrets/clickhouse-ca.crt`. Worker accounts write/read only their private purpose's chunk/record/checkpoint tables; query accounts SELECT only the corresponding purpose records/coverage. Managed ClickHouse roles are `private_audit_worker`, `private_delivery_worker`, `private_operator_audit_worker` and `private_audit_reader`, `private_delivery_reader`; worker roles have SELECT/INSERT on their own record/chunk/checkpoint/coverage tables, and readers SELECT on record/coverage only. See `hrms-clickhouse/grants/0006-protected-private-history.sql` before provisioning. Query bindings may verify multiple explicit companies with distinct proof keys, but must never contain private event encryption keys. The company worker rejects any encryption key outside its exact UUID/purpose.

The event image runs as `node` (UID/GID1000). Provision each worker/query secret directory so that this container user can traverse that directory and read only its mounted files; use reviewed file ownership with0600 files or a dedicated readable group with0640 files and0750 directories. Keep every purpose/company mount distinct and never make keys world-readable. Host environment files remain0600 because Compose reads them before container startup. Verify the effective container user against the mounted files before release; do not recursively change ownership of existing company or platform data.

History reads also require accepted, restored and unrevoked legacy export coverage in source authority and ClickHouse. Missing coverage is an unavailable result, never an empty history. Provisioning files alone does not satisfy the migration or restore acceptance gates.

## Release and retirement boundary

Only `mode=organization` with a nonempty company manifest is accepted. This release contains no `kabipay-outbox-worker` binary or alternate unbound tenant/HMAC layout. Inventory and provision every active company before cutover; reconcile old pending/uncertain deliveries, export/restore history and complete source authority/reader migration gates before retiring an old worker. The release refuses every running container in the owned `apps` Compose project whose effective command or entrypoint contains the retired `kabipay-outbox-worker` executable, including renamed company workers, absolute paths and shell launches. The old global service-label guard and exact global container name outside that project remain checked. Listing/inspection failure blocks rollout; no container is stopped automatically. Rollback uses separately retained previous release artifacts and reviewed authority state. Company membership/grants/manager relationships remain configurable in the organization workspace; infrastructure identity/key/database provisioning is a separate operator responsibility. First organization creation uses the separately authorized `bootstrap_organization <company-uuid> <organization-name>` CLI and `KABIPAY_ORGANIZATION_BOOTSTRAP_TOKEN`, as described in [the organization service runbook](../../docs/runbooks/organization-service.md#first-organization-and-subsequent-administration); the token must never enter command history or a fleet env file.
