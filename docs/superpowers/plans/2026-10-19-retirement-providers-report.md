# Delivery providers and legacy entity cleanup

Date: 19 October 2026. Local implementation; no commit, live migration, deployment or real receiver acceptance.

## Supported API providers

Analytics outbox inspection reads protected delivery history and original source pending intent frames, retaining the existing GraphQL fields, original event UUIDs, directory-management permission and module filters. Historical raw `outbox_event` rows preserve their original fields. New webhook intents group by original event ID before the remote limit, so destination fanout does not underfill the event list. Equal original IDs with conflicting aggregate, event, payload or timestamp fail explicitly. Compact source destination receipts supply current statuses, lease count, processing time, accepted time and safe outcome codes. Unknown outcomes remain visible.

Webhook log inspection merges raw legacy logs with new protected webhook attempt records. Finance attempts are excluded. New records contain safe outcome diagnostics, never worker-selected endpoints, signing keys or receiver response bodies. Existing entitlement redaction remains in the resolver; event metadata permits the same module checks for new webhook attempts.

The source-only reader uses the existing history mTLS client and proof helpers with a fixed delivery path and distinct HMAC domains. Client configuration is `KABIPAY_PRIVATE_DELIVERY_HISTORY_CLIENT_FILE`; its fixed HTTPS endpoint is `/internal/private-events/delivery-history`. Server configuration is `KABIPAY_PRIVATE_DELIVERY_HISTORY_SERVER_FILE`, default port `PRIVATE_DELIVERY_HISTORY_PORT=8446`. Existing history TLS certificate/key/CA variables are shared. The process receives protected delivery SELECT credentials only. No shared reader receives source PostgreSQL credentials or publication encryption keys.

Requests bind current tenant/generation, request UUID, time, exact JSON hash, typed filters and all three accepted original delivery archive identities/hashes. Initial accepted restored archives remain readable after the destructive authorization TTL and after source generation advances; revoked evidence and stale transport proofs remain rejected. Current-generation destructive/capture gates are unchanged. Raw archived JSON crosses the signed API as exact strings; Rust validates its hash before decoding, retaining large integer values.

Pending source frames are read in a repeatable-read snapshot, UUID pages and authenticated complete frames. Remote history pages use descending original event timestamp/UUID cursors. Status-filtered queries scan candidate pages under a 20-second/64-MiB deadline/budget and return an explicit availability error if complete matching history cannot be established. Unfiltered top-N reads remain bounded. Missing coverage or a missing required source receipt is an error, not an empty history.

## Source authorized replay

`requeueOutboxEvent` retains its original GraphQL signature and checks directory-management permission plus current tenant/module entitlement. It authorizes only current-generation RETRYABLE/PERMANENT destinations; delivered destinations remain untouched. Active or UNCERTAIN outcomes require explicit reconciliation. Source receipt row locks fence state changes. Missing cleaned terminal payload frames can be restored only from the authenticated original immutable intent after its hash matches the receipt. Partial/conflicting source frames fail closed.

The source transaction writes an actor-bound audit and fresh encrypted `delivery_replay` command, resets eligible receipts to PENDING and preserves original IDs and absolute lease generation. No new receipt, retry queue or database poller is created. The command carries only original intent reference/hash, destination/version, source generation, base lease and bounded fresh retry budget. The parent owns broker replay parsing/work-model changes and review. Infrastructure separately reproduced and fixed the cleanup/replay receipt-lock race; that PostgreSQL evidence is in its report.

Added only new files under `hrms-database/provisioning/private-events`: native `provision.ps1`, company/operator/registration SQL templates, shared transactional initialization/grant guard, README and focused tests. No 0124/0125 migration edit is part of this ownership.

Company initialization checks the exact active metadata registration through a separate fixed operator libpq service, then validates the actual source database, case-preserving schema, every local tenant_id and publication source_tenant_id. Legitimate foreign actor/source references in organization command receipts remain valid and cannot determine the owning source identity. Metadata scope is explicitly supplied and its schema is fixed to kabipay_ops. The source identity is seeded only as PREPARED with false cutover flags and an explicit generation (initial default 1). Empty versus existing legacy rows is explicit; neither path fabricates archive, reader-switch, pending ownership, capture or retirement acceptance. Missing inventory or an advanced/different existing authority is rejected rather than reset.

Existing source-local business grants are retained. Broad effective PUBLIC, inherited, outside-schema or protected-column permissions fail for operator correction. A narrow authority UPDATE(updated_at) grant permits PostgreSQL SELECT FOR SHARE; no authorization or acceptance predicate depends on that timestamp.
