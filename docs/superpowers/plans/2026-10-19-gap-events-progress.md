## Implemented contracts

- Runtime worker requires `CONSUMER_ROLE=inbox|history|reporting`. Groups are `<KAFKA_GROUP_ID>.<role>.v2`, independent PostgreSQL checkpoints and full-version/event-ID hash fences. Inbox never constructs or calls ClickHouse. History and reporting write separate `business_history` / `reporting_history` stores. Historical membership classification retains protected history without current projections; unknown/PENDING pairs remain metadata-only quarantine. Sticky quarantine is never automatically cleared by later success.
- Source `capture_once(bound_db,tenant)` performs at most100 expanded snapshot rows and a source-owned capture marker transaction. Markers bind source tenant/org/member ID/version, source LSN/time and explicit expanded bootstrap completion. Source resumes reset expanded snapshots per membership epoch.
- Raw Debezium marker coordinator checks fixed source database/schema/table/logical prefix, original marker LSN, persisted Connect source `lsn` AND `lsn_commit`, then emits barriers to EVERY configured company-topic partition. This prevents cross-topic producer batches from being overtaken by a marker on another topic. Each independent group acknowledges its own barriers only after preceding records and its own sink ACK. `organization_capture_healthy(org,tenant,roles,max_age_seconds)` checks accepted historical bootstrap, exact current epoch, marker freshness, full partition/role ACKs and live metadata. Worker uptime/one partition heartbeat cannot satisfy it.
- Connector payload JSON expansion is disabled: a strict one-level JSON string unwrap preserves heterogeneous source payload field sets instead of injecting schema-derived null fields. Original event whitelists/provenance/conflict checks remain mandatory after decoding.
- Supported facts: attendance source status, nullable observed seconds/overtime/late/early quantities; leave exact requested centidays and source dates/status; project-labelled logged/approved seconds. There is no inferred productivity, task completion or prorated leave consumption. `attendance_daily`, `leave_totals`, `project_progress_daily` read latest corrected/tombstoned reporting facts, with decimal integer strings at API boundaries. Unknown attendance duration stays null with a separate unknown count.
- `administration.changed` is metadata only: `{resource_type,resource_id,action,status}`. Normal source emitter requires ACTIVE membership and a closed resource/action mapping. Separate payroll job trigger preserves original immutable actor reference and QUEUED/RUNNING/SUCCEEDED/FAILED/CANCELLED transitions for recognized same membership IDs, including revoked/suspended execution failures. Unchanged-state lease updates are not invented business transitions; capture completeness uses source LSN/barriers, not contiguous resource version numbers.
- Source export jobs snapshot bounded retained outbox or genuine legacy `audit_log` ranges under source-owned cutoff/locks, then commit <=200-row immutable chunks with original IDs, exact PostgreSQL JSONB UTF8 bytes/per-row SHA256, contiguous range/cursor manifests and manifest SHA256. Legacy audit exports retain typed source IDs/actor/time/entity/action/status mapping and original-row hash, never arbitrary before/after state/IP/user agent. Unmapped labels are explicit UNMAPPED; pre-recording intervals remain UNKNOWN. Current metric snapshots are authoritative state facts, not reconstructed legacy actions.
- Source-only `source-export-cli.mjs` uses fixed deployment-bound company credentials and topic, validates source database/membership, reuses immutable chunks after restart, writes exact manifests and publishes original IDs with broker ACK before source-persisted publication checkpoint. Shared consumers never receive company database credentials. Replay validators enforce hashes, scope, IDs, chunk order and range continuity before publish.
- Archive sidecar uses public-only existing RS256 service proof (`kabipay-organization-archive`, exact tenant/POST/path/body hash, <=60seconds) plus mTLS, fixed tenant/org allowlist, source range/capture fences and before/after checks. AES256GCM authenticates manifest, IDs/count/ranges/per-event hashes and plaintext/ciphertext SHA256. Exact source envelopes preserve submillisecond timestamp precision. UUID-only files under configured protected root; atomic no-overwrite publication, file synchronization, full decrypt verification before registration, key versions/read keyring and authenticated orphan recovery. Per-ID PostgreSQL transaction locks serialize concurrent exports/retries. Historical retrieval compares immutable archive epoch and recognized same membership ID; current central history/export ALL remains root's requirement.
- History TTL deletion is explicitly disabled (`DELETE WHERE 0`) until accepted archive/retention policy; idempotent DDL replaces reporting views when upgrading.
- Bounded outbox cleanup defaults dry-run and targets ONLY fixed company/control outboxes, never receipts/audit/business tables. Execution requires trusted operator enable config, exact fixed source/database/schema scope, accepted persisted retention policy, minimum age/batch/restore requirements, current accepted evidence lease/cutover, exact locked IDs/hashes/range and final expiry/capture rechecks. Tests add a synthetic DB+nonce gate; production execution is not performed. Legacy consumer cutover checks stopped broker group and unchanged final offsets plus replacement coverage before recording acceptance. Outboxes remain the transactional CDC handoff until a separately accepted durable alternative exists.
