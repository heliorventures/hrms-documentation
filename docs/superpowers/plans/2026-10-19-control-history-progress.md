# Control history and structured-log ingestion

## Implementation

Owned files are only `hrms-svc/integrations/organization-events` and `hrms-svc/infrastructure/organization`; company-event worker code is unchanged. New separate control consumer validates native Debezium metadata source identity and fixed topic, typed actor/envelope and exact per-event change schemas. It preserves NULL-organization identity facts in protected `organization.control_history`, with separate operator `security_audit` and current sticky capture checkpoint. It has no PostgreSQL connection or tenant credentials. Dedicated control Connect has only fixed restricted metadata credentials, separate secret mounts/ACL/internal topics and no company source network.

Control history retains both monotonic outbox sequence and separate configuration revision. Exact same event ID/content replays deduplicate; event-ID/aggregate-sequence conflicts are hash-only quarantined. The control topic has exactly one partition, checked at startup, and only one writer group is supported. Required synchronous history/checkpoint or quarantine acknowledgements precede broker commits. Replays after uncertain acknowledgement are safe; later valid events do not erase quarantine state. Current checkpoint is observed activity, never automatic capture attestation or all-history proof. New `command.cancelled` strict schema retains references/operation/version only.

Deployment assets include restricted metadata CDC grants, connector/binding templates, separate private control Connect/worker Compose, CH DDL/grants/row policy guidance, retention/backup/replay/cleanup gates and app query contract in `control-history.md`. No control outbox deletion is enabled.

Opt-in source filelog templates use official contrib collector0.162.0 pinned to verified GHCR manifest `sha256:39923a8e431bd1f57be82411999d389fcfe40857492e4365456d97a4c1f74be6`. Exactly one approved Docker JSON log file is mounted read-only; no Docker socket or broad host logs. Docker wrapper/time and Rust structured JSON are parsed, arbitrary messages/private/token/span/user/tenant/org fields removed, severity/code narrowly whitelisted and company/service provenance assigned from fixed deployment metadata. Filesystem state and queues are bounded/persisted; exports use private mTLS. `filelog.md` documents rotation/remount, source binding and backend routing/retention limits.

## Limits

No production deployment, production mTLS/ACL/backend routing/retention/backup restore, complete historical backfill or central admin API E2E is claimed. Control capture remains NOT_ATTESTED until separately reconciled. Ordinary org admin must not query NULL-org global security history. Business/security history retention reference is seven years; diagnostics backend default30days must be separately deployed/checked. Exact file binds require reviewed remount on rotation/container recreation. Root owns central admin API and UI; this worker never broadens company-topic trust.
