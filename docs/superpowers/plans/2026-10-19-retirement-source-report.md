# Source maintenance and private delivery implementation

Date: 2026-10-19. Owner: source-maintenance/delivery agent. Local source changes only; no commit, deployment, live migration or external delivery acceptance.

## Changes

- Added independently deployable `hrms-svc/crates/kabipay-tenant-maintenance`. The original source business jobs were extracted from the old outbox worker with their existing domain service calls, tenant business clock, entitlement gates, privacy/dedupe rules and batch bounds: due separation/access/session revocation, attendance expiry(50), survey transitions, celebrations, performance cycle/deadline processing, company upload stages(25), announcement video stages(25), private-file cleanup(25). The maintenance binary uses bound-tenant registration/source databases and `KABIPAY_TENANT_MAINTENANCE_POLL_MS` (default2000,250–60000). Startup requires an explicit bound company configuration and aborts if absent. It has no delivery queue polling or HTTP egress execution/signing credentials. As an offboarding event producer it still needs scoped private publication keys and the same source destination snapshot/version/keyref policy as other producers.
- Removed these scheduler invocations from `kabipay-outbox-worker`; retained its legacy transport implementation until the coordinator completes all producer/reader/export/cutover ownership changes. Scheduler and outbox transport cannot continue competing for the same sweep loop after cutover.
- Finance terminal writes now atomically call common `enqueue_delivery` in the original Employee transaction. Intent identity is terminal operation UUID; destination is fixed Payroll identity/version1; payload contains only operation reference. Both COMMITTED and CANCELLED event names remain. Deleted Employee's `finance_worker.rs` and old `services/finance_outbox.rs`; startup mounts the source adapter instead. Payroll loan/FNF coordination and recovery were not modified by this task.
- Added common `private_webhooks::{LegacyWebhookEvent,enqueue_webhooks}` for coordinator-owned legacy producers. All11 names are exact/explicit, including offboarding. It keeps original v1 body/event ID while making intent identity deterministic per event/destination, snapshots subscription config_version under a share lock, includes optional source-only platform destination, bounds fanout at256 subscriptions, and records explicit NO_DESTINATION outcomes. Existing notifications remain in their business services. Legacy subscription hashes never become outbound signing keys.
- Added `employee/services/private_delivery.rs`, deterministic `private_delivery_policy.rs`, `private_egress_policy.rs`, and private HTTP route. Full wire contract and local key file format are in `private_delivery_contract.md`. Shared callers send signed immutable references only, never URLs, payload replacements, source credentials, client JWTs or signing keys.

## Security and concurrency

- Verify tenant/generation-scoped HMAC proof, immutable intent hash, destination/version, timestamp, request UUID and exact lease fence before source execution. Decrypt complete source-owned frames with current tenant/purpose keys and authenticate each frame's source generation. Current database source authority, immutable receipt and decrypted intent must all agree.
- Lease0 is signed status-only. Only exact current+1 claims PENDING/RETRYABLE. Same request never resends; already accepted destinations return their durable receipt after acknowledgement loss. Expired PROCESSING becomes UNCERTAIN rather than automatically executing again. Statuses remain distinct. Source-authorized, audited reconciliation is required to reenable a terminal uncertain/permanent receipt; shared broker proof alone cannot do this. Nondelivery intent frames must remain source-local until final disposition, or a future protected source-owned restore adapter must recover and verify the original encrypted frames before reexecution.
- Initial claim uses receipt row lock. An independent dispatch transaction holds source authority and receipt locks plus subscription share lock across bounded egress, fencing concurrent source rollover or subscription config updates. This is separate from the originating business transaction. Lock timeout3s, statement timeout5s, dispatch idle timeout30s, lease45s; real lease comparisons use PostgreSQL clock_timestamp, not transaction-frozen NOW.
- Finance reconstructs a fresh existing signed Employee-to-Payroll request, rereads authoritative terminal Employee operation, and accepts only expected operation/state response. Existing finance_contract verification still binds tenant/request/action/signature/freshness, while Payroll performs its existing authoritative readback and transactional FNF/loan reconciliation. Adapter requires a fixed HTTPS Payroll URL. Common finance transport now disables implicit proxies.
- Webhook endpoints come from fixed source subscription/platform config only. HTTPS443, exact host allowlist, rejection of nonpublic/special-use IPv4/IPv6, all-address DNS checks, request DNS pinning, no proxy, no redirect, 3s DNS/connect and15s total request timeouts,128KiB body bound. Response bodies are never buffered, logged or persisted. v1 timestamp/HMAC signing is retained with stable delivery/idempotency headers. Source-only signing key references must resolve to explicit validated key material. Platform endpoint/keyref/version hash is authenticated inside its encrypted intent so an environment endpoint change cannot reroute queued work under an unchanged version.
- HTTP2xx remains the existing at-least-once acceptance contract; no exactly-once receiver effect is inferred. Ambiguous transport/Finance responses become UNCERTAIN. Definite429/5xx are RETRYABLE; redirects/other rejection statuses are PERMANENT.
