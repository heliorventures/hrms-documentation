The prior active-only retention statement above is superseded: discarding all inactive-company events loses valid business facts committed before suspension/detach but delayed in Kafka. New narrow0116 `organization_capture_member_classification` locks metadata in organization→tenant→membership order and returns ACTIVE only for current effective org/tenant/membership with exact installed revision/runtime ACTIVE; HISTORICAL for known accepted ACTIVE/SUSPENDED/DETACHING/DETACHED pairs; NONE for unknown/PENDING-only. Worker has EXECUTE only, never private tenant SELECT or metadata UPDATE.

HISTORICAL applies the same strict topic/actor/payload/version/hash/conflict checks and appends protected ClickHouse business history only. No inbox, directory or current projection fence changes; checkpoint becomes sticky PARTIAL/HISTORICAL_MEMBERSHIP only after sink acknowledgement. NONE is hash/position-only quarantine with no fact or projection/watermark row. Current application membership/grant/capture-epoch read fences remain in force. No occurred_at membership-start filter is used, because bootstrap facts intentionally predate membership. There is no membership epoch in current event schema and no cryptographic generation cutoff is inferred. Resume/reattachment requires separate current capture acceptance/reconciliation.
